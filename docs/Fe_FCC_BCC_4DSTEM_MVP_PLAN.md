# Fe-FCC/BCC 合成 4D-STEM 验证：最小可行项目计划

**版本**：v1.0 · 2026-09-25  
**对象**：`large-4dstem-analysis` 的数据读取、Bragg 峰检测、倒易空间标定、相鉴定及基础取向识别  
**工作环境**：Windows + ReciPro + 现有 Conda 项目环境

## 1. 项目目标与完成定义

建立一份**可复现、具有独立晶体学参考和已知真值**的小型 Fe-FCC/BCC 合成扫描数据，实际运行现有分析脚本，并输出能够指出具体失败环节的报告。

第一版只回答以下问题：

1. 相同像素坐标和标定条件下，脚本能否检测到预期的 Bragg 峰？
2. BCC 与 FCC 的结构模型、消光和倒易尺度是否正确传入相鉴定模块？
3. 从单相到四晶粒双相扫描，脚本能否给出正确相图，以及有依据的低置信度标记？
4. 若脚本已经输出取向，能否识别预设带轴与面内旋转？

**完成定义**：T01、T02、T03 三组数据均能从现有 CLI 读入和处理；输出机器可读的预测结果及 `validation_report.json`；报告记录通过与失败的指标、失败位置及完整配置。即使识别不通过，只要报告能复现并定位错误，本项目作为**诊断基准**仍算建成；算法通过与否另列结论。

**范围边界**：此数据集是将独立模拟的单晶花样按预设空间图排列的 *synthetic 4D-STEM benchmark*。它没有模拟真实探针在各扫描位置的多重散射，不据此证明真实材料中的相鉴定准确率。首版不做应变、晶界混合图样、厚度序列、Bloch 波或 abTEM 多切片模拟。

## 2. 开工前必须核验的输入

### 2.1 当前已有 CIF 的核查结果

已检查现有三个文件的实际晶体数据：

| 文件 | 标注空间群 | 晶格和原子坐标所表达的结构 | 用途 |
|---|---|---|---|
| `Fe.cif` | Fm-3m，225 | FCC；a = 3.65555117 Å | 首选 FCC 输入 |
| `Fe (1).cif` | P1，1 | 同一 FCC 常规胞的四个 Fe 位置 | 仅作“对称性元数据丢失”的附加对照 |
| `Fe (1)(1).cif` | P1，1 | 与上一个文件相同的 FCC 原子位置 | 不另作一个相 |

**当前缺少 BCC CIF。** 不得把任一 P1 文件作为 BCC。先准备一个明确的 Im-3m（229）Fe-BCC 常规胞，例如 a≈2.866 Å、Fe 位于 (0,0,0) 和 (1/2,1/2,1/2)；核对生成文件的单胞、占位、空间群与模拟器导入结果。BCC 与现有 FCC 的晶格常数只作为本基准的输入条件，不暗示它们在相同温度下共存平衡。

验收时同时检查结构因子消光：BCC 的 (100) 禁戒、(110) 允许；FCC 的 (100)、(110) 禁戒、(111) 允许。这里的检查是**运动学结构因子检查**，不将真实 TEM 中可能出现的动力学禁戒反射视为软件错误。

### 2.2 环境和接口检查

- 记录 ReciPro 版本、现有脚本 commit、Python/py4DSTEM 版本、两份 CIF 的 SHA-256、全部生成参数与随机种子。
- 先用现有项目 CLI 确认 HDF5 自定义 loader 的数据集路径、轴顺序、整数类型，以及能否在单次运行中指定两个相的 CIF；对不上时只做必要的适配。
- 在 Windows 实机运行一次 ReciPro 宏：导入 CIF，输出 `[001]` 的 PNG 和 `SpotInfo()` CSV。官方文档确认这些宏调用及外部控制能力；**CSV 的列名、坐标系、单位和强度含义仍须以实际导出样本检查**。
- 明确该 CSV 是否提供足够的数值信息重建探测器：反射 hkl、二维位置或可转换的倒易坐标、强度。若缺字段，则 PNG 仅供目测，不声称其像素值是电子计数；先采用其他具有数值峰列表的独立模拟来源，记录替代原因。

**Gate 0（必须通过）**：两份 CIF 确属不同点阵；各导出一张可读花样；找出至少两组允许反射并核对禁戒反射；确定数值峰列表到 `q_x,q_y`（Å⁻¹）的变换，或明确替代数值来源。

## 3. 固定的 v1 实验条件

| 项目 | v1 配置 | 备注 |
|---|---|---|
| 相 | Fe-BCC（新核验 CIF）；Fe-FCC（已有 `Fe.cif`） | 固定两个候选，不从真值文件读取候选答案 |
| 电压 | 300 kV | ReciPro 宏中的能量单位按软件核对，记录为 keV |
| 取向 | BCC [001]、BCC [011]；FCC [001]、FCC [111] | 每相至少一个易区分的基准取向 |
| 面内角 | 0°、25°、10°、35°，依上列次序 | 定义图像正方向和旋转正号；只在确认可复现导出后启用 |
| 探测器 | 256 × 256；中心 (127.5,127.5) px | 图像索引采用 `[q_y, q_x]`，相机坐标另行定义 |
| 倒易采样 | 目标 0.020 Å⁻¹/px | 先由导出 CSV 的单位和尺度校验，不靠 PNG 显示尺寸猜测 |
| 探测窗口 | 按目标采样约 ±2.56 Å⁻¹ | `q_max`/FOV 与导出峰裁剪条件一起记录 |
| 峰形 | v1 固定相同的二维 Gaussian 核 | 仅模拟点斑在探测器上的宽度；不声称是严格 CBED 盘 |
| 噪声 | T01–T03 为无噪声、无漂移 | 允许无随机性的量化为 `uint16`；保留量化前峰列表 |
| 扫描 | 单相 8×8；双相 32×32 | 32×32×256×256×uint16 的原始字节数为 128 MiB |

选择目标采样时，要保证多个有判别力的反射在视场内，且峰间距离足够分辨。**不要直接复用旧数据集的 `probe_radius=18` 或 `inv_Ang_per_pixel=0.0192` 作为合成数据真值**；先确认参数语义和是否经 binning。若实际 ReciPro CSV 没有物理二维倒易坐标，先做单位换算和少量反射手工核对，再决定像素比例。

## 4. 交付数据格式与真值约定

建议使用普通 HDF5，由项目自定义 loader 显式读取；不把它冒充 py4DSTEM 原生 EMD：

```text
benchmarks/Fe_FCC_BCC_v1/
  inputs/Fe_FCC.cif, Fe_BCC.cif
  reference/recipro_export/*.csv, *.png, export_manifest.json
  datasets/T01_BCC_001.h5
  datasets/T02_FCC_001.h5
  datasets/T03_four_grains.h5
  truth/T01_truth.npz, T02_truth.npz, T03_truth.npz
  runs/<run_id>/predictions/*
  runs/<run_id>/validation_report.json
  runs/<run_id>/config_snapshot.yaml
```

各 HDF5 的最小约定：`/datacube/data` 为 `(scan_y, scan_x, detector_y, detector_x)`、`uint16`；`/metadata` 保存电压、倒易采样、中心、轴方向、CIF 哈希、模拟器版本、成像核、强度归一化与生成器版本。**真值另存 `truth/*.npz`，分析 CLI 不读取真值目录**；评估程序只在预测结果落盘之后读取。

真值至少包含：`phase_id[scan_y,scan_x]`（0=BCC，1=FCC）、`grain_id`、`pattern_id`、每个模板的 `(h,k,l,q_x,q_y,intensity)`、每像素导出取向标识及生成时使用的像素变换。若要评估连续取向误差，还必须保存可核验的 crystal→lab 三维旋转矩阵及对称性约定；若 ReciPro 导出无法提供或重建该矩阵，v1 仅比较离散带轴/面内角，不报告虚假的“三维取向误差”。

**坐标契约**：给出 `q_x=(col-c_x)·Δq_x`、`q_y=s_y·(row-c_y)·Δq_y`，其中 `s_y` 的取值与右手坐标系和图像向下增长方向一致，并在元数据中固定。用至少三个非共线反射手工检查变换的尺度、符号及 90°/180° 翻转。反射真值只覆盖视场内、满足事先定义的强度阈值且可分辨的峰。

## 5. 实施步骤、责任输出及关卡

| 阶段 | 操作 | 实际输出 | 通过条件 |
|---|---|---|---|
| A. 核验输入 | 准备 BCC CIF；检查已有 FCC；锁定软件版本及 CLI 输入要求 | `inputs/`、`manifest` | Gate 0 完成；相与空间群、基底坐标一致 |
| B. 独立参考 | 用 ReciPro 导出四个指定取向的 PNG + CSV；记录设置；检查 hkl、位置和强度字段 | `reference/` | 四个图样可重做；明确二维倒易尺度；消光、首几组反射可解释 |
| C. 数据生成 | 从数值反射列表栅格化（包括直射束）；固定峰核与比例；写入 8×8/32×32 HDF5，并独立保存真值 | 3 个 HDF5 + `truth/` | 形状、dtype、中心、非负强度、无削顶、重复生成哈希一致 |
| D. 项目运行 | 将 HDF5 路径和两相 CIF 传给现有 CLI；同一套配置跑 T01–T03；只做必要 loader 适配 | `runs/<run_id>/predictions/` | 所有数据处理结束；输出可解析峰、标定、相图与 QC 信息 |
| E. 评估定位 | 逐项比较峰、标定、相、QC、离散取向；绘制错误点和残差图 | `validation_report.json` + 简短 README | 每一指标有分母、阈值、失败实例、版本与配置快照 |

### T01/T02：最小单相验证

- T01：8×8 BCC [001]，同一张数值模板布满扫描；T02：8×8 FCC [001]。
- 数据生成前核对 `[001]` 的可见反射。对于理想零级区轴衍射，BCC `[001]` 的 `hk0` 中 `h+k` 必须为偶数；FCC `[001]` 的 `hk0` 中 `h,k` 必须同为偶数（或在投影及激发容差下按实际规则判读）。这些细项由结构因子列表自动核对，避免将“110 允许”误说成它在 `[001]` 图样中一定出现。
- 两相候选同时提供给相鉴定器；不按数据集名称强制指定正确相。逐图检查峰中心、排序、模板覆盖率、得分和 `ambiguous` 标记。
- 若 T01/T02 失败，按“结构与对称性 → q 单位和图像翻转 → 中心束及检测阈值 → 模板取向覆盖 → 匹配/QC”顺序排查，不开始 T03 的调参。

### T03：四晶粒双相验证

- 32×32 扫描分为四个 16×16 区域，每区一个 `pattern_id`：BCC [001]/0°、BCC [011]/25°、FCC [001]/10°、FCC [111]/35°。
- 每个区域内固定相和取向，边界为整像素且没有混合花样；在报告中分别统计每区指标和全图指标。该测试可检验相图、离散取向、区域标记及全局 BVM 对两相的影响。
- 同时用局部单图和全局平均/BVM 做诊断；**相鉴定最终指标以逐扫描位置的预测为准**，全局 BVM 只用于解释偏差。测试前冻结同一分析配置，避免单独给某区域定制阈值。

## 6. 指标、阈值与报告解释

下面是 v1 的**预注册目标**，不是既有性能事实。只有 Gate 0 确认反射可观测、CLI 输出齐备之后才锁定最终分母和阈值；变动须在报告记录。

| 指标 | 计算方法与分母 | v1 目标 |
|---|---|---|
| Bragg 召回率 | 可观测且与其他峰分离的非中心真值峰，在 1.5 px 内与检测峰一对一配对 | T01/T02 ≥90% |
| Bragg 位置误差 | 配对峰的像素欧氏距离中位数；同时报告 90 分位数 | 中位数 ≤1 px |
| 中心位置误差 | 拟合的 `(c_x,c_y)` 与模拟真值的距离；若 CLI 没有输出则标为“不可评估” | ≤1 px |
| 倒易尺度误差 | `abs(estimated−truth)/truth`；仅在当前脚本确实估计尺度时评估 | ≤1% |
| 单相识别 | T01/T02 分别统计正确、错误、拒判/ambiguous 像素 | 两组各 ≥95% 正确且拒判 ≤5% |
| T03 相图 | 所有 1024 像素中正确/错误/拒判数量；各晶粒单列，拒判不计正确 | 总体 ≥95% 正确；每区 ≥90% |
| 取向 | 首先比较带轴类别和面内角；立方对称及图像翻转等价须在评估器中处理 | 仅在输出可对齐的取向时报告 |
| QC | 输出拒判率、错误高置信度率、覆盖率；计算分母明确 | 不设事后迎合阈值；无噪声失败必须列原因 |

报告还须给出相鉴定**混淆矩阵（行是真值 BCC/FCC，列是 BCC/FCC/拒判）**、每晶粒的 score margin 分布、峰匹配配对清单、最差十个扫描位置及 `run_id`。如果零噪声数据的峰检测很好但相鉴定失败，报告中要区分模板/结构模型错误、取向搜索未覆盖和 QC 门槛过严；不得仅用提高总体准确率掩盖这些差异。

## 7. 最少实现文件与命令接口

将小型基准代码放在现有项目的 `benchmarks/fe_fcc_bcc/`，避免改造分析主流程：

```text
benchmarks/fe_fcc_bcc/
  README.md                  # 环境、运行步骤、坐标约定
  config.yaml                # 版本、几何、阈值、随机种子
  inspect_cifs.py            # 检查结构和消光，输出摘要
  export_recipro.py          # Windows 实机调用/指导导出；保存原始 CSV/PNG
  build_dataset.py           # 数值峰列表 -> HDF5 + 隔离的 truth/*.npz
  evaluate.py                # 读预测+真值 -> JSON/误差图
```

期望 CLI 形式（**接口目标，实施前按仓库实际参数调整**）：

```powershell
python benchmarks/fe_fcc_bcc/inspect_cifs.py --fcc inputs/Fe_FCC.cif --bcc inputs/Fe_BCC.cif
python benchmarks/fe_fcc_bcc/export_recipro.py --config benchmarks/fe_fcc_bcc/config.yaml
python benchmarks/fe_fcc_bcc/build_dataset.py --config benchmarks/fe_fcc_bcc/config.yaml
# 接着按项目现有 CLI 分别运行 T01、T02、T03，保存完整命令和配置。
python benchmarks/fe_fcc_bcc/evaluate.py --run-dir benchmarks/Fe_FCC_BCC_v1/runs/<run_id>
```

`export_recipro.py` 必须对实际 `SpotInfo()` 的表头做校验，拒绝无法解释的单位、空表或坐标缺失。构造 `uint16` 时先对每张花样采用**统一**强度变换，再加入可记录的直射束，并检查没有溢出或截断；不允许每张花样各自自动拉伸导致相间强度不可比。重复像素可通过 HDF5 压缩节约磁盘，但仍须实际用脚本加载检查。

## 8. 时间安排与暂停规则

| 时间预算 | 任务 | 可交付检查点 |
|---|---|---|
| 第 1 天 | 核验 CIF、项目 loader 和 ReciPro 实机 CSV | Gate 0 摘要；若 CSV 不可用，记录替代方案 |
| 第 2 天 | 生成 T01/T02；运行现有分析；修正明确的数据接口错误 | 单相报告与代表性峰叠图 |
| 第 3 天 | 生成 T03；运行同一配置；汇总误差与 QC | 双相混淆矩阵、逐区表和失败案例 |
| 第 4 天（预留） | 复跑核验、整理 README、固定哈希和提交基准 | 可复现的 v1 基线 |

**暂停规则**：没有 BCC CIF 或不能取得可解释的独立数值峰坐标时，不生成标为“已验证”的双相数据；不能确定取向矩阵约定时，只评估相和离散带轴；若只有 PNG，先做可视化核对，不将它当作定量计数真值。若脚本没有可导出的峰列表/相图，可先加最小导出接口，再评估相应指标。

## 9. v1 完成后再扩展

按一次只增加一种困难的顺序：T04 固定噪声与峰缺失 → T05 已知中心漂移、尺度误差和小角度偏轴 → T06 用独立生成方式构造可追踪形变，再研究应变；最后使用 abTEM 的 `GridScan` + `PixelatedDetector` 做具有空间扫描物理意义的小数据交叉验证。每次沿用 v1 的坐标约定、固定配置和报告格式。abTEM 的 4D-STEM quickstart 已提供这类扫描与探测器示例，但其引入属于后续阶段。
